# Architecture / product decision log

| ID   | Decision                                                                           | Reason                                                                                           | Status                                                                                                               |
| ---- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| D001 | Private season-long fantasy, not daily contests                                    | Draft, rivalry and retention are the core thesis                                                 | Accepted                                                                                                             |
| D002 | Free leagues, no wagering or monetary prizes                                       | Social product without a real-money contest                                                      | Accepted                                                                                                             |
| D003 | MLC first; separate competition/season entities                                    | Clear source boundaries and later IPL path                                                       | 2026 replay implemented; other releases not claimed                                                                  |
| D004 | Mobile-first web before native apps                                                | One accessible codebase and shareable invitations                                                | Implemented                                                                                                          |
| D005 | **Six managers, 15 drafted each, 11 starters + 4 bench**                           | User explicitly selected this format; real 102-player pool supports six complete squads          | Accepted 2026-11-04, settings v2; replaces original 10/8/2 proposal                                                  |
| D006 | Snake draft, exclusive ownership per fantasy league                                | Real private-league behavior, not globally unique ownership                                      | Implemented; transactional 90-pick and independent-league HTTP smoke                                                 |
| D007 | Average each starter's actual eligible appearances in a fantasy window             | Reduce extra-match volume advantage without summing schedules                                    | `mlc-v0.1` coefficients unchanged; experimental fairness, full-precision storage and display-only rounding           |
| D008 | 2026 historical replay before live stats                                           | Deterministic source/audit work before a provider contract                                       | Implemented through champion; not live service                                                                       |
| D009 | Next.js/TypeScript, Supabase Auth/Postgres, existing Vercel deployment             | One pragmatic web/multiplayer stack                                                              | Existing Free/Hobby resources retained; no duplicate projects or upgrade                                             |
| D010 | Original identity; no copied Sleeper assets or first-in-category claims            | Respect IP and distinguish experience from invention                                             | Accepted                                                                                                             |
| D011 | User-scoped SSR + RLS + narrow transactional/read RPCs                             | Identity and league authority remain in the database, no browser privilege key                   | 24-table RLS and fifteen exposed RPCs reviewed; fifteen intentional definer warnings retained                        |
| D012 | Hash-only, expiring, rotating invitations and no pre-join league preview           | Convenience without private-name disclosure or stored raw secrets                                | Implemented; normal invitation continuation verified                                                                 |
| D013 | Node 22 and trusted generated preview email origins                                | Avoid untested runtimes and request-header-selected callbacks                                    | Applied; canonical/current Auth callbacks read back through authenticated CLI                                        |
| D014 | Shared dark sports system with distinct mobile/desktop navigation                  | Dense real league information, consistent identities and accessible interaction                  | Implemented; 48 current viewport checks, axe/manual follow-up                                                        |
| D015 | Separate normal PKCE and token-hash confirmation protocols                         | Keep default hosted mail usable while supporting local/custom templates                          | Genuine default confirmation/recovery exercised locally; no admin-confirmed success claim                            |
| D016 | Explicit historical **Lock & replay**, not wall-clock locking against past dates   | A replay must remain editable until its commissioner settles a window                            | Implemented; future live timestamps/locks remain a separate mode                                                     |
| D017 | Visible polling and member-triggered expired-turn resolution                       | Persist authoritative state without pretending there is an always-on timer worker                | Five-second draft / twenty-second other polling; real expiry/reconnect verified                                      |
| D018 | Publish source windows before picks; instantiate fantasy pairings after final pick | Separate fixed cricket windows from resolved league seat/team identities                         | Implemented source calendar and transactional schedule creation                                                      |
| D019 | Freeze advanced bracket identities during source corrections                       | Recalculate auditable scores without silently replacing participants of an advanced/locked round | Implemented; explicit limitation, not a retroactive bracket-repair claim                                             |
| D020 | Explicit fantasy-derived eligibility, official corroboration only where available  | Cricsheet lacks a complete official-position dataset; do not invent verified roles               | Source policy/version and keeper URLs visible; broader role/balance validation remains alpha work                    |
| D021 | Preserve email confirmation and Free/Hobby plans                                   | No security bypass or purchase to fabricate hosted email readiness                               | Default sender/SMTP and real-group acceptance remain explicit gates; Pro-only leaked-password warning not suppressed |

Accepted/experimental rule changes must be explicit and versioned. The format change does not change `mlc-v0.1` point coefficients. Repeatable engine results, real local Auth and green infrastructure checks are not claims of production SMTP, human adoption or competitive fairness.
